# 作品让项目多了什么

决赛「2 分钟项目贡献」的陈述稿，以及每一句话背后可以核对的证据。

## 一句话

OctoBuddy 给 OctoSense 加了一条应用生产线：一句话请求 → 多个 agent 分工做出来 → 宿主核对、发布 → 上线后自己巡检、出事自己修。这条线上「算不算完成」由宿主核对，不由 agent 自己说了算。

## 2 分钟讲稿

> OctoBuddy 给 OctoSense 加的是一条应用生产线。别的应用的 agent 发一句请求，用户点「开始做」，外环拆任务，几个内环用不同的 agent 并行做，OctoBuddy 跑检查、提交、发布到 App Hub；发布之后它每五分钟自己跑一遍，坏了就交给外环修、发修复版——这是官网悬赏里的「生产回路 Agent」。
>
> 这次我们做的最重要的事，是让这条线上「算不算完成」不再听 agent 的。内环说测试通过，OctoBuddy 拿它自己跑的结果去对；对不上，先退回去，外环也验收不了，除非写明理由给用户看。每一次提交、发布、提交审核都留回执，做完马上读回核对；重复点发布不会多发一个版本，中途退出也不会重做。别的 agent 发来的文字一律当资料，不当指令。
>
> 对项目本身：OctoBuddy 已经以原生应用的形态提了 PR #344 编入 OctoSense，按初赛评委的意见 rebase 到最新 main，CI 的每一步在 PR head 上本地都过了，生成器加了回归测试；它现在等维护者审。我们给做 OctoSense 应用的 agent 准备了运行、点击、试跑 Splash 的工具，cookbook 和模板仓库，任何参赛者都能用它来做应用。

## 防夸大

- 说「PR #344 已提交、可合并、本地按 CI 步骤全过」，不说「已合入」。
- 声明核对与验收闸的端到端证据是 **stub 合成** 的（不调用模型）；除非录屏里真的录到，不说「抓到了真实 agent 撒谎」。
- 「发布读回在真实 App Hub 上跑过」要说清是小账本 0.1.3、提交 `5f58490`。
- v0.2.x 的生产回路实测停在「Repair 交给外环」那一轮；v0.3.0 的完整闭环以录屏为准。
