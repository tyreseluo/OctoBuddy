# 演示录屏：脚本与说明

决赛 3 分钟演示用的录屏，以及录屏时一并要留下的截图。录完后把下方「录制说明」填好，和视频一起放在这个目录（视频较大时放 Release 附件，这里留链接与 sha256）。

## 准备

- **构建**：OctoSense 用 PR #344 的分支（`feat/octobuddy-app`），OctoBuddy 钉到 v0.3.0（发布后 PR 的 pin 会移过去）；在那之前，本机用 path patch 指向 OctoBuddy 的工作副本构建（不提交）。
- **启动**：`OCTOSENSE_HUB=~/.octobuddy/hub` 等环境按 OctoBuddy 发布成功时会话里给出的那一行设置，OctoSense 的 App Hub 才会列出本地发布的应用。
- **模型**：外环 Claude Code（自己的登录）；内环用 AI providers 里启用的模型（例如 MiniMax、GLM），各切片可不同。
- **加快巡检**：应用的 `.octobuddy/card-loop/watch.json` 里写 `"every": 30`（秒），录屏时不用等 5 分钟。
- **录屏**：⇧⌘5 录整个屏幕或 OctoSense 窗口；打开「显示鼠标点按」。

## 流程（目标：3 分钟内讲完，长等待处快进并在画面上标注）

| # | 操作 | 画面上应看到 | 截图文件 |
| --- | --- | --- | --- |
| 1 | 在 OctoSense 系统 agent 的对话里说一句：「做一个上海天气卡片，API 挂了也要显示上次的数据」 | 系统 agent 调 `octobuddy.request`；侧栏脉冲按钮变色；应用页出现请求卡片：谁请求的、做什么、验收标准 | `01-request-card.png` |
| 2 | 点「开始做」 | 新会话，请求以 `<untrusted source="app-request:…">` 资料块出现在输入框；选外环、内环模型后发送 | `02-brief-fenced.png` |
| 3 | 等外环拆任务、内环并行实现（快进） | 流程图上外环 → 几个内环；每个内环结束时会话里一行 `[commit] … · [receipt] ✓ … · [tests] … passed · [claims] ✓ / ? …` | `03-claims-receipt.png` |
| 4 | （若出现）检查没过或声明被驳 | `[claims] ✗ …`，「OctoBuddy 先把汇报退回一次」；外环 accept 被拒，或外环带 override 验收、会话里写明理由 | `04-gate.png` |
| 5 | 外环停下后，在卡片上点「发布」 | 按钮旁写着将要发布的内容（摘要、版本）；会话里「已发布 … 到本地 App Hub」，下一行回执：✓ 读回 catalog 条目、摘要、内容、提交 | `05-published-readback.png` |
| 6 | 再点一次「发布」 | 「已发布为 x.y.z，未重复」 | `06-not-repeated.png` |
| 7 | 打开 Live 页 | 这个应用：已发布版本、健康、最近运行的圆点、「上次发布：✓ 已读回核对」 | `07-live-baseline.png` |
| 8 | 点「演练：坏版本」 | 坏版本发布；下一次巡检判 broken，事故开启，会话收到 | `08-incident.png` |
| 9 | 点「修复」（或打开「自动修复」） | 外环拿到简报（报障与屏幕文字在 `<untrusted>` 块里），定位原因并修复，不整版回退 | `09-repair.png` |
| 10 | 点「发布修复版」 | 修复版回执 ✓；下一次巡检正常 → 「✓ 巡检：… 恢复正常 … 修复版 x.y.z」，并列出每一步用时 | `10-closed-on-fix.png` |

讲解时对应的话：第 3、4 步讲「agent 说的要对照事实」；第 5、6 步讲「做完马上读回、不重复做」；第 8–10 步讲「上线后自己发现、自己修，修复版跑通才算结案」。声明被驳（第 4 步）在真实运行里不一定出现；没出现时，用 [e2e 输出](../claims/e2e-2026-10-11.txt) 说明，并讲明那是 stub 合成的。
